# Sounds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Short, punchy sound effects for every weapon, movement and world event, heard from where they
happen, plus a hit sound and a "Sun kill!" announcer, in solo and online.

**Architecture:** A pure module (`src/client/sounds.js`, no DOM) turns each frame's events and the change in
world state since the last frame into a list of one-shot sounds and a set of looping sounds, each with a
position. A Web Audio engine (`src/client/audio.js`) plays them with 3D panning from the camera, a distance
cut-off and a voice limit, using recipes made from oscillators, noise and filters (`src/client/synth.js`).
The announcer is the only sound file. `src/sim/` stays silent; it gains two event fields.

**Tech Stack:** plain ES modules, Web Audio API, Node 22 `node:test`, Playwright via `npx` for checks, Piper
(open-source speech tool, installed outside the repo) for the announcer file.

**Spec:** `docs/superpowers/specs/2026-10-28-sounds-design.md`

## Global Constraints

- No npm packages in the page, no bundler; three@0.160.0 from the import map. Sounds are made in the browser
  with Web Audio, except one announcer audio file in the repo.
- Our own sounds, in the spirit of Quake 3; never copied from any game.
- `src/sim/` imports nothing from three.js or the DOM; `src/net/` no DOM or Node-only APIs. Sound code lives
  in `src/client/`.
- Every gameplay number lives in `src/tuning.js`; sound volumes and distances are looks-only numbers there
  too (`SOUND`, like `FEEDBACK`).
- Online, the hit sound plays only from the server's confirmation; your own actions sound at once.
- Settings default to "on" (`settings.get` returns true for unknown names), so the names are `"sound"` (all
  sound) and `"hits"` (the hit sound), both on by default. Keys: M toggles sound, H toggles the hit sound.
- No music. Only "Sun kill!" from the announcer this round.
- The announcer voice and the speech tool must have licences that allow publishing the file in this public
  MIT repo; a credit goes in the README if the licence asks. Nothing for the announcer is installed inside
  the repo or committed except the final audio file.
- Docs and comments brief, explain why, no em dashes. Tests: `node --test 'tests/*.test.mjs'`. Commits end
  with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing is pushed or deployed.

## Review Focus

1. Online duplicates: your own pad launch, beam or rocket blast arrives twice (predicted here, then echoed by
   the server). Each must sound once. Pinned in Task 2.
2. Pile-up: a minigun burst, ten shotgun pellets or a chain of asteroid blasts must not stack into a roar or
   clip. A voice limit and per-name rate limit apply. Pinned in Task 3 (limiter test) and Task 2 (one fire
   sound per shot, not per pellet).
3. A hidden tab coming back: the events and state changes of the gap must not all play at once. Pinned in
   Task 2 (a frame after a gap longer than `SOUND.gap` produces no state sounds) and Task 4.
4. Audio blocked until the first click, or an `AudioContext` that fails to start: the game runs silently,
   never throws. Pinned in Task 4.
5. Respawn and reset: a respawn or a server reset (clock back to 0, entities replaced) must not read as a
   burst of footsteps, shots or pickups-back. Pinned in Task 2.

### Task 2: What to play (pure)

**Files:** Create `src/client/sounds.js`. Modify `src/sim/weapons.js` (beam event gains `owner`),
`src/sim/asteroids.js` (burn event gains `pos`), `src/client/online.js` (server events are tagged
`remote: true`), `src/tuning.js` (`SOUND`). Test: create `tests/sounds.test.mjs`.

**Interfaces:**
- `SOUND = { range: 120, near: 6, own: 1, others: 0.7, gap: 0.5, stride: 1.6, stepSpeed: 2, maxVoices: 24,
  repeat: 0.05, announcerOthers: 0.4 }` (m, m, gain, gain, s, m, m/s, voices, s between two plays of one
  name, gain). Starting values; looks only.
- `createDirector({ selfId, online }) -> { frame(world, events, dt, settings) -> { once: Sound[], loops: Map<key, Sound> } }`
  where `Sound = { name, pos | null, own: bool, gain?: number }` and `pos` null means "in your head" (no panning).
  The director keeps the last frame's per-entity state (`shots`, `weapon`, `hook`, `fuel`, `groundId`,
  stride distance, alive) and pickup `readyAt`s, and diffs against it.
- Sound names (the full list; Task 3 makes one recipe per name): `pistol`, `shotgun`, `rocket`, `minigun`,
  `sniper`, `railgun`, `rocketFlight` (loop), `explode`, `rockIncoming` (loop), `rockBurn`, `ding`, `hurt`,
  `death`, `announcer`, `boink`, `pickup`, `pickupBack`, `step`, `hookFire`, `hookPull` (loop), `boost`
  (loop), `switch`, `empty`.

Rules (each one a test):
- **Events:** `hit` with `by === selfId` gives `ding` (the dummy included; none if `settings.get("hits")` is
  false); `hit` with `id === selfId` gives `hurt` (in your head). `death` of self gives `death` (in your head); of others, `death` at `pos`. A `death` with cause
  `"sun"` and `by === selfId` gives `announcer` (in your head, full); with another `by`, `announcer` at
  `SOUND.announcerOthers` gain for everyone else. `explode` gives `explode` at `pos`; `burn` gives `rockBurn`
  at `pos`; `launch` gives `boink` at the entity; `pickup` gives `pickup` at the entity; `beam` gives
  `railgun` at `from` only when `owner !== selfId` (your own railgun sounds from your shot counter).
- **Online duplicates:** when `online`, an event with `remote: true` that your own prediction already
  produced is skipped: `launch` with `id === selfId`, `explode` whose `id` starts with `${selfId}.`.
- **State:** an entity's `shots` going up gives one firing sound named by its weapon at its eye (once per
  shot, not per pellet); `weapon` changing gives `switch` for self only, or `empty` when the old weapon's
  ammo is 0; `hook` going from null to set gives `hookFire`, and while set a `hookPull` loop keyed
  `hook:<id>`; fuel falling while airborne gives a `boost` loop keyed `boost:<id>`; walking on the ground
  faster than `stepSpeed` gives a `step` every `stride` metres travelled; a pickup whose `readyAt` passes the
  clock gives `pickupBack` at the pickup. Loops: `rocketFlight` per rocket projectile (`rocket:<id>`),
  `rockIncoming` per asteroid (`rock:<id>`).
- **Gaps and resets:** a frame with `dt > SOUND.gap`, a clock that went backwards, an entity seen for the
  first time, or a respawn (alive false to true) updates the remembered state but produces no state sounds
  for it. Events still sound (they are already capped by the online events limit).

### Task 3: How it sounds (Web Audio recipes, engine, sound test page)

**Files:** Create `src/client/synth.js`, `src/client/audio.js`, `sounds.html`, `src/client/soundtest.js`,
`tools/sound_check.cjs`. Test: `tests/audio.test.mjs` (the pure parts).

**Interfaces:**
- `RECIPES` (synth.js): `{ [name]: (ctx: BaseAudioContext, out: AudioNode, opts) -> { stop?() } }`, one per
  name in Task 2's list; loops return `stop`. Built only from Web Audio nodes (oscillators, noise buffers,
  filters, gain envelopes, delays). Each one-shot lasts at most 1.5 s.
- `createAudio({ AudioContextImpl = globalThis.AudioContext }) -> { unlock(), setListener(pos, forward, up),
  play(sound), setLoops(Map), setEnabled(bool) }`: one `AudioContext`, created on `unlock()` (the first
  click), with a master gain and a compressor. Positional sounds go through a `PannerNode` ("HRTF",
  "inverse" distance with `SOUND.near` as refDistance) and are skipped beyond `SOUND.range`; `own` sounds
  play at `SOUND.own`, others at `SOUND.others`. A limiter keeps at most `SOUND.maxVoices` voices and drops
  a name played again within `SOUND.repeat` s. If creating or resuming the context throws, every method does
  nothing.
- Pure helpers exported from audio.js for tests: `audible(dist) -> bool`, `admit(state, name, now) -> bool`
  (the limiter).
- `sounds.html` + `soundtest.js`: a plain page listing every name as a button (loops as toggles) and the
  announcer, so the owner can listen to each one. Linked from nowhere in the game; the README mentions it.
- `tools/sound_check.cjs <url>`: Playwright opens the sound test page, renders every recipe in an
  `OfflineAudioContext` (2 s, 44.1 kHz) and prints per name the peak, the RMS and the time to fall below
  -50 dB, then `OK` if every one-shot is audible (peak above -30 dB), never clips (peak at most 0 dB) and
  ends within 1.5 s, and every loop is audible and steady (RMS of its second half within 6 dB of its first).

- [ ] **Step 1: Write the failing tests** (`tests/audio.test.mjs`): `"beyond SOUND.range nothing is

  `"createAudio with a throwing AudioContext does nothing and never throws"`, `"every sound name from
  sounds.js has a recipe"` (import the name list from sounds.js; synth.js must load under node without
